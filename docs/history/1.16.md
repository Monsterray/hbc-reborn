# HBC 1.16.x: findings and hardware results

What each 1.16.x change found, fixed and measured, newest first. The short list of
changes is in [CHANGELOG.md](../../CHANGELOG.md); open items are in
[review.md](../review.md).

## 1.16.1: the Updated badge clears, the call log fits, the agent shrinks

Also in 1.16.1:

- Updated badge: an amber light inside the button's top edge that fades
  downward, following the button's outline, instead of a 3 px line.
- Start-up call log: a fast poll that repeats takes one row with a count
  (`repeats`, `last_out`), so the drive scan no longer fills the log.
- hbc_agent: the overlay's and the Log page's big buffers are allocated only
  while used (overlay static memory 45.7 KB → 4.7 KB, agent 29.2 KB → 8.6 KB).
- HBCS adds `uptime_ms`, `net_longest` and `accepts`; `hbc.py send` sees a
  new HBC by its uptime. `tcp_close` waits in 10 ms slices (longest network
  call 3.6 s → 0.5 s on a Wii); `hbc.py` polls HBCS less hard.
- Tests: `ensure_hbc` skips re-sending the running build; Dolphin tests poll
  instead of sleeping and run together with `tests/dolphin/run_all.py`; new
  `tests/wii/wii_app_badges.py` and `tests/wii/wii_port_outage.py`; lrwii
  is a bench Wii (only prod is refused).

Checked on the dev Wii, 2026-11-10: `wii_app_badges` ALL PASS (new 0, after a
run 0, changed boot.dol 482-486 amber pixels focused or not, identical send
clears it, sort_id-only change 0). All 22 Dolphin tests pass. Open: IOS's
TCP stack sometimes stops answering port 4299 for about 2.5 minutes (open
item in [review.md](../review.md), [research/ios-tcp.md](../research/ios-tcp.md)).

### Two causes of the Updated badge staying on

- Trigger (dev Wii, 2026-11-09): `hbc.py order` rewrites `meta.xml` to set
  `<sort_id>`, so every reordered app turned Updated; and an app installed in
  `sd:/apps/X` and launched by `hbc.py send`/`run` was never recorded, so it
  stayed Updated for good.
- Fix: `apps_seen.txt` stores `meta.xml` as an FNV-1a hash of its text without
  `<sort_id>...</sort_id>` and without white space around tags (`meta.xml=h:HEX8`).
  An old `meta.xml=SIZE@TIME` stamp still parses and is judged by size and time
  until the app's next run (which rewrites it, even when nothing changed). A network
  launch whose HBCA caption is `<app>/boot.dol|elf` records `sd:/apps/<app>` when
  the bytes sent equal that folder's file (size, then content; checked before the
  loader touches the data). Other uploads record nothing.
- Check: `tests/host/test_apprun.py` (sort_id-only change, real edit, old-format line,
  upload match and its refusals); `tests/dolphin/dolphin_app_badges.py` has a
  new `<sort_id>` step; on the dev Wii, `tests/wii/wii_app_badges.py` confirmed that
  `hbc.py send sd:/apps/X/boot.dol` clears X's Updated pill.

## 1.16.0: release; a stuck USB drive no longer holds HBC on a black screen

The release of 1.15.1 to 1.15.21 (details in [1.15.md](1.15.md)). The headline:

- A reset with a USB drive mid-transfer used to leave HBC on a black screen
  until the drive was pulled. HBC now finds the stuck drive at start-up,
  frees IOS with a software unplug, and starts with its menu up; until the
  drive is pulled, a menu launch warns first and a network launch is refused.
- [sdk/usbguard](../../sdk/usbguard/README.md) gives other apps the same
  protection: guarded USB calls, mounts and IOS reloads, a warning screen, the
  software unplug and the wait for a replug. Public domain.
- `hbc.py status` lists HBC's timed start-up calls, and the TV shows them when
  the menu is late.

Also since 1.15.0: the audit fixes of 1.15.2-1.15.12, the slot light library
fixes (1.15.13-1.15.15), `hbc.py send --no-wait`, a pulled drive leaving status,
and a file that is not a DOL being refused instead of crashing HBC. The old
forwarding headers `sdk/hbc_agent.h` and `sdk/hbc_netlog.h` are gone; use
`-I<hbc-reborn>/sdk/hbc_agent` and `-I<hbc-reborn>/sdk/hbc_netlog`.

For contributors: the repository is reorganised (tests by where they run, docs
in `docs/`, every SDK in its own folder), and `tools/hooks/pre-push`
(`git config core.hooksPath tools/hooks`) stops a push that carries Wii keys,
signing keys, dumps or tokens.

Checked on the dev Wii, 2026-11-09, HBC 1.15.21 installed as OHBC, with Monty
at the Wii:

- Stuck USB (`tests/wii/wii_usbguard.py`, d2x usb-spin, job
  20261109-094510-6f5895): ALL PASS. After each of two watchdog resets HBC
  freed the stuck drive and its menu was up at about 1.6 s. Round 1: HBC's
  launch warning, the app's warning at 5.0 s, the pull seen, and a mount after
  the replug. Round 2: the software unplug freed the stuck call (FREED).
- Replug (`tests/wii/wii_replug.py`, job 20261109-095750-d23029): 6 of 8 steps
  passed. Known issue: after both devices were out, an SD card plugged in
  after the USB drive is not found until HBC restarts (open item "The SD card
  is not found again after both devices were out").
